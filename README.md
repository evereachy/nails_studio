# ATELIER — лендинг салона красоты (MVP)

Next.js 15 (App Router) · TypeScript · Tailwind · Framer Motion.
Mobile-first: мобильная версия — основной сценарий, десктоп — расширение.

```bash
npm install
cp .env.example .env.local
npm run dev
```

---

## Главный принцип: три независимых слоя

Дизайн, контент и логика не пересекаются. Поэтому под клиента меняется только нужный слой.

| Что меняем | Где | Компоненты трогаем? |
|---|---|---|
| Цвета, шрифты, радиусы, тени, отступы | `src/app/globals.css` (`:root`) | нет |
| Тексты, контакты, часы работы | `src/config/site.ts` | нет |
| Услуги, цены, длительность | `src/config/catalog.ts` | нет |
| Отзывы, FAQ, галерея | `src/config/content.ts` | нет |
| Состав и порядок блоков | `src/config/blocks.ts` | нет |
| График работы, шаг слотов | `src/config/schedule.ts` | нет |
| Куда уходит заявка | `src/services/notifications/` | нет |

Смена всего оформления — один атрибут в `src/app/layout.tsx`:
`<html data-theme="sand">` → `sand` | `noir` | `rose` | пустое (базовое).

## Карта блоков — что где стоит

Порядок задаётся массивом `pageBlocks` в `src/config/blocks.ts`.

| # | Блок | Файл | Задача | Мобильное поведение |
|---|---|---|---|---|
| 1 | Hero | `src/blocks/Hero.tsx` | Кто мы + начать запись без скролла | Фото на весь экран, карточка выбора прижата к низу |
| 2 | About | `src/blocks/About.tsx` | Доверие: текст + 3 факта | Факты в 3 колонки |
| 3 | Services | `src/blocks/Services.tsx` | Прайс, вход в запись | 1 колонка, фото слева 80×80 |
| 4 | Booking | `src/blocks/Booking.tsx` | Ядро: сама запись | Кнопка → шторка на весь экран |
| 5 | Reviews | `src/blocks/Reviews.tsx` | Социальное доказательство | Лента scroll-snap, карточка 82vw |
| 6 | Gallery | `src/blocks/Gallery.tsx` | Показать работы | Мозаика 2 колонки |
| 7 | FAQ | `src/blocks/Faq.tsx` | Снять возражения | Аккордеон |
| 8 | Footer | `src/blocks/Footer.tsx` | Контакты, часы, соцсети | Отступ снизу под нижнюю панель |

Сквозные элементы (вне списка блоков):

- `components/layout/Navbar.tsx` — шапка. На мобиле только логотип и кнопка звонка.
- `components/layout/StickyBookBar.tsx` — нижняя панель «Записаться». Появляется после первого экрана.
- `features/booking/BookingSheet.tsx` — шторка записи, монтируется один раз.

### Как добавить свой блок

1. Создать `src/blocks/MyBlock.tsx`, обернуть контент в `<Section eyebrow title lead>`.
2. Добавить строку в `pageBlocks` в нужное место массива.

Отступы, ширина контейнера и типографика заголовка приедут из `Section` — вручную ничего не выравниваем.

## Слой записи

```
features/booking/
  BookingProvider.tsx   состояние на всё приложение (черновик, шаг, статус)
  BookingFlow.tsx       оркестратор шагов + панель кнопок
  BookingSheet.tsx      обёртка в шторку
  api.ts                единственное место, где фронт знает про транспорт
  steps/
    StepService.tsx     1. услуга
    StepWhen.tsx        2. дата + время
    StepContact.tsx     3. имя, телефон, комментарий
    StepDone.tsx        4. подтверждение
```

Состояние общее, поэтому карточка в Hero, кнопки в «Услугах» и нижняя панель ведут
в один и тот же сценарий и не теряют уже сделанный выбор.

**Логика слотов** — `src/lib/slots.ts`. Слот доступен, если процедура целиком
помещается в рабочий день и не пересекается с занятыми интервалами.
Услуга 180 мин, старт 09:00 → занято 09:00–12:00, слоты 09:30…11:30 гаснут.
Занятость сейчас mock (`src/config/schedule.ts`), сигнатура `getBusyIntervals()`
не изменится при переезде на БД.

## Уведомления

```
services/notifications/
  types.ts     интерфейс NotificationChannel
  telegram.ts  реальная реализация
  stubs.ts     заглушки email / whatsapp / sms
  index.ts     реестр каналов + notifyBooking()
```

Каналы включаются переменной `NOTIFY_CHANNELS=telegram,email`.
Без ключей канал работает в dry-run: пишет в консоль вместо отправки — демо
показывается клиенту без реального бота.

Новый канал = файл с реализацией `NotificationChannel` + строка в реестре.

### Telegram

1. `@BotFather` → `/newbot` → токен.
2. Добавить бота в группу, взять `chat_id` (`https://api.telegram.org/bot<TOKEN>/getUpdates`).
3. Заполнить `.env.local`.

Формат сообщения — `buildMessage()` в `telegram.ts`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/book` | создать запись, разослать уведомления |
| `GET` | `/api/book?date=&serviceId=` | свободные слоты |

Валидация дублируется на сервере, включая повторную проверку занятости слота —
защита от гонки, когда двое записываются на одно время.

Хранилище — `services/booking-repository.ts`, сейчас в памяти процесса.
Переезд на Prisma / Supabase / Firebase = новая реализация интерфейса
`BookingRepository`, API-роут не меняется.

## Что специально сделано для мобильной версии

- Высоты через `100dvh`, не `vh` — адресная строка Safari не срезает низ экрана.
- `env(safe-area-inset-bottom)` на нижней панели и в шторке — контент не уезжает под полосу жестов iPhone.
- `font-size: 16px` у всех полей ввода — Safari не зумит страницу при фокусе.
- `type="tel"` + `inputMode="tel"` — цифровая клавиатура сразу.
- Все интерактивные элементы ≥ 44–48px по высоте.
- Дата выбирается лентой дней, а не нативным календарём ОС — один тап вместо модалки.
- Кнопка действия закреплена внизу шторки: палец не тянется через весь экран.
- Шторка закрывается свайпом вниз, `overscroll-contain` не даёт скроллиться странице под ней.
- `-webkit-tap-highlight-color: transparent` — нет серой вспышки по тапу.
- Ленты через нативный `scroll-snap`, без JS-слайдера: инерция родная для системы.
- Нижняя панель прячется, когда открыта шторка — кнопка не дублируется.
- `prefers-reduced-motion` отключает анимации.
